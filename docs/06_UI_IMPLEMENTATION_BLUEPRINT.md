## 1. 产品界面的核心原则

TerryDirector 是 **镜头生成任务编排工作台**，不是传统 NLE，也不是以播放器为核心的视频编辑器。

用户的主路径：

```text
选择时间线片段
      ↓
编辑提示词
      ↓
从项目资产池引用素材
      ↓
设置生成规格
      ↓
提交生成
      ↓
查看生成过程反馈
      ↓
继续编排下一个片段
```

任何新功能进入常驻界面前，都必须先回答：

> 它是否直接服务于“编排镜头生成任务”？

如果答案是否定的，不增加常驻面板。

---

## 2. 部署形态与 UI 边界

TerryDirector 最终不是桌面应用。

```text
ComfyUI Custom Node
        │
        ├─ 共用 Python / GPU / Workflow / Queue
        ├─ 共用 input / output / temp
        │
        └─ 启动 TerryDirector 本地 Web 工作台
                     ↓
              独立本地端口
```

ComfyUI 节点只承担：

- 服务状态
- 当前项目摘要
- 打开工作台入口

完整时间线、提示词、资产池和生成预览都在 Web 工作台中。

不要重新引入 Tauri、独立桌面 Runtime、Bridge、独立任务引擎或为未来假设场景设计的大量中间层。

---

## 3. 面向用户的术语

面向用户统一使用：

- **片段**
- **时间线片段**
- **资产池**
- **参考资产**
- **生成预览**
- **后续联动**

不使用 `Segment` 作为 UI 文案。

内部代码可以选择稳定的英文类型名，但不能渗透到用户界面。

## 4.2 外壳

工作台不是贴浏览器边缘的全屏平面。

外壳要求：

- 浏览器四周留白：`clamp(24px, 6vmin, 80px)`
- 外部背景：深灰蓝，而不是纯黑
- 视觉约为 `#242632 → #1D1F29`
- 应用本体有圆角和细亮边
- 使用明显但柔和的下方投影
- 同时保留贴近外壳的接触阴影

目标是类似最初配色参考图的“设备浮在背景上”的层次，而不是网页卡片感。

当前外壳阴影由 Theme Contract 统一控制，业务组件不得自行增加另一套大阴影。

# 6. 提示词编辑区

提示词是主要创作区域。

## 6.1 顶部压缩结构

当前固定节奏：

```text
片段身份行        44px
提示词工具行      28px
下间距             6px
─────────────────────
合计              78px
```

不能重新膨胀成大标题区。

片段身份行：

- 片段编号
- 可编辑片段名称
- 当前片段时长 / 重叠摘要

工具行：

- 提示词
- `@ 引用素材`
- `/ H3 语法`
- 可视化 / 纯文本

---

## 6.2 一份 Prompt，两种编辑表现

每个片段只保存一份 Prompt。

```text
clip.prompt
     │
     ├─ 可视化编辑
     └─ 纯文本编辑
```

两种模式不是两份数据。

切换模式必须：

- 不丢换行
- 不丢标签
- 不改变原始 H3 语句
- 不生成隐藏副本

当前不做 AI 增强，不显示 AI Prompt 标签页，不显示“采用增强结果”。

---

## 6.3 可视化编辑器

可视化模式 **必须可编辑**，不是预览器。

支持：

- 输入
- 删除
- 换行
- 选中
- 复制
- 剪切
- 粘贴
- Undo / Redo
- 中文输入法组合输入

格式化标签的可见中文只是表现层，原始文本仍保存为 H3 语法。

全选复制时不能遗漏格式化标签。

---

## 6.4 `@` 资产菜单

`@` 菜单读取 **整个项目资产池**。

不是只读取当前片段已有引用。

菜单显示：

- 图片 / 视频 / 音频
- 项目稳定编号
- 文件名
- 图片缩略图
- 搜索 / 过滤

选择后在当前光标位置插入对应引用。

点击已有资产引用标签可以更换绑定素材。

---

## 6.5 `/` H3 菜单

来源以 Terry H3 Prompt Editor 为准。

保留五类：

- 结构
- 镜头
- 对白
- 保留关系
- 任务类型

镜头分类下保留镜头运动子菜单和全部 **20 种运镜**。

菜单交互：

```text
↑ ↓      选择
→        进入分类
←        返回
Enter    确认
Tab      确认
Esc      关闭
继续输入  搜索
```

支持：

- 镜头编号修改
- 说话人编号修改
- 时间戳修改
- 运镜切换
- 对白语言切换
- 对白正文直接编辑

`non_diegetic_music:` 插入时下一行默认 `N/A`。

## 6.6 标签视觉

统一基础几何：

- 最小高度约 **28px**
- 内容行高约 **20px**
- 行内垂直居中
- 素材缩略图约 **20×20**

内容语义色：

| 内容 | 颜色 |
| --- | --- |
| 结构 / 镜头 / 运镜 | 紫色 |

# 7. 项目资产池

中间列不是“当前片段参考列表”。

它是：

> **项目级全局资产池**

切换时间线片段时：

- 资产列表不变化
- 滚动位置不变化
- 只更新“当前片段正在引用”的轻量状态

---

## 7.1 尺寸

桌面默认资产列宽：

> **680px**

仍允许拖动分隔线调整，双击恢复该默认值。

资产网格默认：

- 一行约 4 格
- 缩略图高约 **52px**
- 紧凑卡片
- 素材增加后自动换行
- 资产列内部滚动

不要恢复大卡片或单张素材占半栏的样式。

---

## 7.2 资产池入口

顶部只保留两个入口：

### 上传资产

用户选择新的图片 / 视频 / 音频。

正式实现中：

```text
用户文件
  ↓
TerryDirector
  ↓
ComfyUI 管理的 input
  ↓
加入当前项目资产池
```

### 从 ComfyUI input 选取

用于复用 input 中已经存在的素材：

- 浏览子目录
- 搜索文件名
- 多选
- 已入池标记
- 不重复上传

这两个入口必须明确区分。

不要再增加：

- “从项目选取”
- 网格末尾“添加素材”卡片

因为资产池本身已经是项目素材浏览器。

---

## 7.3 稳定编号

项目级素材按类型稳定编号：

```text
Picture 1
Picture 2
Video 1
Audio 1
...
```

编号：

- 只在加入项目时分配一次
- 切换片段不变化
- 删除其他素材不重排
- 删除后的编号不立即复用

UI 的编号是项目稳定引用。

提交具体模型工作流时，如模型要求局部连续编号，由编译层转换，不能让 UI 自己猜。

---

## 7.4 引用与删除

片段引用资产有三种方式：

```text
资产卡片「插入引用」
@
把资产拖到目标时间线片段
```

删除提示词中的引用标签：

> 只取消该片段的引用。

资产池“删除”：

> 项目级删除。

必须确认受影响片段，并清理这些片段中的对应引用。整个删除过程应支持一步 Undo。

资产池删除不能删除 ComfyUI input 中的原始磁盘文件。

---

## 7.5 查看素材

点击素材主体：

> 打开独立大图 / 视频 / 音频灯箱。

不能把素材塞进右侧生成预览窗。

关闭灯箱时停止媒体播放并释放播放状态。

# 8. 生成预览区

生成预览是 **常驻第三列**。

它不是工作台视觉中心，也不是完整播放器。

## 8.1 预览窗

- 16:9
- 始终占据布局
- 不隐藏
- 不折叠
- 不回收列宽

预览开关只控制：

> 是否显示 / 更新生成过程画面。

关闭时：

- 面板仍在
- 显示“生成预览已关闭”
- 生成任务继续
- 进度继续
- 参数仍可修改
- 不重排三列

---

## 8.2 真正实现时的数据来源

正式版生成预览优先复用 ComfyUI 原生采样预览数据流。

参考 TimelineDirector / SelfLift 路径：

```text
Sampler
  ↓
latent preview callback
  ↓
TerryDirector preview transport
  ↓
常驻生成预览窗
```

不要再创建第二套昂贵的中间解码系统。

生成预览绑定正在运行的任务，而不是绑定当前编辑选择。不能因为用户切换片段，就把另一个片段的参考素材伪装成生成结果。

# 9. 生成参数

生成参数固定放在 **生成预览窗下方**。

提示词区底部不再摆这些参数。

---

## 9.1 分辨率选择

使用 ComfyUI Resolution Selector 同一逻辑：

```text
画面比例
像素量 MP
尺寸倍数
      ↓
实际 Width × Height
```

支持比例：

- 1:1
- 2:3
- 3:2
- 3:4
- 4:3
- 9:16
- 16:9
- 21:9

计算：

```text
total_pixels = megapixels × 1024 × 1024
scale = sqrt(total_pixels / (ratioW × ratioH))

width  = round(ratioW × scale / multiple) × multiple
height = round(ratioH × scale / multiple) × multiple
```

默认：

```text
16:9
1.2 MP
multiple 32
→ 1504 × 832
```

实际宽高结果是普通信息，不用橙色抢焦点。

---

## 9.2 生成动作

预览开关：二级紫色状态。

主生成按钮：

> **最高优先级橙色**

这是右侧操作区最醒目的动作。

> **整数帧**

## 10.3 总编排时长

总时长是高优先级信息。

固定在“新建片段”之后。

视觉：

- 标签较弱
- 数字 **20px**
- 橙色
- 等宽字体

计算：

> 从 0 帧到所有片段最大的 `endFrame`

因此：

- 首部空隙计入
- 中间空隙计入
- 重叠不重复相加
- 视图滚动留白不计入
- 空项目 = 0

当前播放头时间单独显示为“当前位置”，保持中性，不与总时长竞争。

# 12. 重叠

重叠是 **派生状态**，不是独立对象。

```text

+
片段 B 时间范围
       ↓
求交集
       ↓
重叠区
```

用户只操作片段。

不能：

- 选择重叠区
- 拖动重叠区
- 拉重叠边缘
- 直接输入重叠长度

---

## 12.1 重叠视觉

重叠：

- 紫色
- 半透明
- 被动显示

时长气泡：

```text
2s
```

放在重叠框下方。

连接线：

> **8px 短引线**

不能恢复很长的垂直连接线。

重叠紫色与选中片段橙色必须明确区分。

# 13. 片段承接规则

片段承接由时间位置自动推导，用户不需要重复配置同一关系。

## 13.1 首尾吸附：自动引用上一片段尾帧

当相邻两个时间线片段满足：

```text
当前片段.startFrame === 上一片段.endFrame
```

即 **零空隙、零重叠、首尾吸附** 时：

> 当前片段生成时，自动参考上一片段当前输出的最后一帧。

由于内部时间范围是半开区间 `[startFrame, endFrame)`，上一片段的视觉尾帧是：

```text
previous.endFrame - 1
```

该尾帧作为当前片段的边界 / 首帧连续性参考，由编译层注入生成任务。

### 这不是项目资产引用

自动尾帧：

- 不加入项目资产池
- 不占用 `Picture N` 项目稳定编号
- 不在 Prompt 中自动插入手工素材标签
- 不需要用户再次选择图片
- 不作为可删除的普通参考资产卡片

它是 **由时间线几何关系派生出的连续性输入**。

### 条件变化时自动切换

```text
有空隙       → 不自动引用上一片段尾帧
首尾恰好吸附 → 自动尾帧承接
产生重叠     → 使用重叠连续性机制，不再使用“单尾帧承接”规则
```

因此：

- 拖开片段，尾帧承接自动失效
- 再次吸附，尾帧承接自动恢复
- 拖成重叠，进入 overlap / latent continuity 路径

不额外保存一个容易过期的布尔开关。

### 上一片段尚未生成

如果尾帧承接成立，但上一片段尚无可用输出：

- 不伪造尾帧
- 当前片段的生成任务应依赖上一片段先完成
- Queue / Compiler 层负责建立这个生成依赖
- UI 可以显示等待依赖状态，但不增加新的常驻配置面板

# 14. 后续联动

时间线锁链按钮：

> **后续联动**

默认开启。

---

## 14.1 移动

开启时拖动片段 N：

```text
片段 N      跟随
片段 N+1    跟随
片段 N+2    跟随
...
```

前面的片段不动。

整组：

- 同距移动
- 内部片段时长不变
- 内部间距不变
- 内部重叠不变

---

## 14.2 尾部调整

开启后续联动时调整当前片段尾部：

```text
当前片段 endFrame += Δ
后续所有片段 start/end += Δ
```

结果：

- 当前片段起点不变
- 与下一片段原有间距 / 重叠不变
- 后续片段自身时长不变

关闭联动后：

> 只调整当前片段尾部。

---

## 14.3 头部调整

片段头部 Trim：

> 始终只调整当前片段。

不触发后续联动。

---

## 14.4 Undo

一次拖动或裁剪：

> 一次 Undo。

Esc：

> 取消整次操作，所有联动片段一起恢复。

吸附时不能把正在联动移动的片段自身旧边缘作为吸附目标。

后续联动是工具状态，不保存进项目数据。

# 15. 三级信息颜色

全局 UI 信息优先级：

中性灰蓝 / 白灰。

- 普通标题
- 普通按钮

- 分辨率结果

# 17. 响应式

桌面优先。

大屏：

```text
提示词 | 资产池 | 生成预览
```

窄屏：

```text
提示词
资产池
生成预览
时间线
```

要求：

- 不出现页面级横向溢出
- 工作台外壳留白保留
- 菜单始终落在视口内

- 不通过删除按钮文字解决空间不足

# 18. 项目状态与 UI 临时状态

## 项目数据

应保存：

```text
Project
Assets
Clips

Resolution

Generation records / outputs
```

## 派生数据

不重复存储：

```text
Overlap
Tail-frame continuation relation
```

## UI 临时状态

```text

时间线当前缩放
时间线滚动
当前 Hover
菜单开关
灯箱状态
```

# 19. 正式功能接入点

UI 蓝图冻结后，真实功能应从现有界面向后接，而不是先重构前端。

| UI | 正式能力 |
| --- | --- |
| 项目入口 | 项目创建 / 打开 / 保存 |
| 上传资产 | 写入 ComfyUI input，并注册到项目资产池 |
| 从 ComfyUI input 选取 | 服务端目录枚举、搜索、媒体元数据 |
| 资产灯箱 | 读取真实图片 / 视频 / 音频 |
| Prompt 编辑器 | 保存真实片段 Prompt |
| 时间线 | 保存 startFrame / endFrame |
| 首尾吸附 | 自动取上一片段输出尾帧作为当前片段边界参考 |
| 重叠 | 编译成 overlap / latent continuity 输入 |
| 参考引用 | 编译成当前片段 Generation IR |
| 分辨率 | 写入真实生成参数 |
| 生成按钮 | 提交 ComfyUI Workflow / Queue |
| 生成进度 | 读取真实 Queue / Execution 状态 |
| 生成预览 | 接 ComfyUI latent preview |
| 片段底部状态 | 显示真实耗时 / 完成状态 |
| 导出配置 | 导出真实项目配置 |

实现时优先薄接入，不增加“为了严谨”的额外页面或抽象层。

# 21. 实现红线

1. **不要为了接后端重排已经确认的 UI。**
2. 不把生成预览重新做成页面中心。
3. 不把资产池降级成“当前片段参考列表”。
4. 不把重叠变成独立可编辑对象。
5. 不把首尾吸附的尾帧承接做成手工资产引用。
6. 不恢复未选中片段 Hover 白色 Trim Handle。
7. 不移除按钮文字只留图标。
8. 不重新加入 AI 增强和版本管理占位入口。
9. 不让实现层的 Workflow 节点 ID、路径或模型字段直接污染 UI 数据模型。
10. 不为未来假设需求增加复杂架构。
11. Demo 中已经确认的尺寸、颜色和交互，除非用户再次明确修改，否则视为实现验收基线。

# 22. 前端验收清单

正式功能实现后，至少逐项确认：

- 页面结构仍是提示词 / 资产池 / 生成预览 / 时间线。
- 资产池宽度、紧凑卡片与项目级语义没有变化。
- H3 可视化编辑、`@`、`/` 与纯文本往返无损。
- 生成预览始终占位，关闭只停止画面更新。
- Resolution Selector 与 ComfyUI 算法一致。
- 时间线仍为单行。
- 普通片段起点紫色霓虹、选中片段橙色霓虹正常。
- 片段标题 / 状态两行保持拉开。
- 片段自身时长和总编排时长为橙色。
- 选中片段为橙色；重叠和播放头为紫色。
- 重叠时长保持 8px 短引线。
- **首尾吸附时自动引用上一片段尾帧；拉开空隙即取消，形成重叠即进入重叠连续性。**
- 后续联动默认开启，移动和尾部调整行为正确。
- 头部 Trim 不联动。
- 一次手势只产生一次 Undo。
- 未选中片段 Hover 不出现白色 Trim Handle。
- 所有功能按钮保留图标 + 名称。
- 外部深灰蓝背景、四周留白和明显柔和投影保持。
- 没有新增未经确认的常驻功能区。

# 23. 冻结结论

从 **Demo v0.6.11** 开始，TerryDirector 的 UI 设计阶段进入冻结状态。

后续工作重点从：

> “界面应该长什么样”

切换到：

> “如何让这套界面真正驱动 ComfyUI 完成项目、资产、提示词、时间线和生成任务”。

除非出现真实使用问题或用户再次明确提出视觉改动，否则功能实现阶段应以本蓝图作为前端验收标准。
