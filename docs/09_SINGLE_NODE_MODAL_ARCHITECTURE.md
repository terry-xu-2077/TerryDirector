# TerryDirector 单节点与页内浮窗架构

> 决策日期：2026-10-02  
> 状态：用户确认产品形态；本文记录实现边界与待验证接口，不代表功能已经实现。  
> 当前代码仍是 Demo v0.6.13。本轮仅更新文档，不修改 UI、采样代码、依赖或工作流。

## 1. 本轮确认的形态

用户决定：导演台在 ComfyUI 画布上保留为**一个采样器式主节点**，接入模型和采样参数，输出生成结果给下游解码器。节点内仅显示**只读的迷你时间轴**；点击后在当前 ComfyUI 页面打开大浮窗进行完整编辑，保存退出后隐藏浮窗。

因此：

- 不要求用户连接独立的“规划节点 + 生成节点”。
- 不新开浏览器标签页、窗口或独立工作台端口；生产入口改为当前 ComfyUI 页内浮窗。
- 主节点既是编辑入口，也是实际参与工作流执行的节点，不是单纯的服务启动按钮。
- 时间线、提示词编辑器和资产池继续使用已经打磨的原生 HTML / CSS / JavaScript；不引入 React。
- 实现我们自己的节点，不要求安装、连接或在内部调用 Songssx 的节点类。参考成熟源码进行符合许可的移植、整理与适配，保留来源记录。
- 模型、兼容的加速组件及最终保存由用户在 ComfyUI 工作流中配置；不恢复通用工作流导入、标记、发布、动态 UI 平台。

本决策覆盖 `01_PRODUCT_AND_TECH_DECISIONS.md` 与 `06_UI_IMPLEMENTATION_BLUEPRINT.md` 中独立端口、另开网页、画布节点只作入口等旧描述，也覆盖对话中先前的两主节点方案。旧文档用于追溯；未涉及的编辑器、时间线、配色、引用和连续性要求继续有效。QuantFunc 的暂缓接入决定不变。

## 2. 一个可见节点，内部职责仍然分开

画布不拆成两个主节点，不意味着把全部功能写进一个大文件。

```text
编辑浮窗 → 已保存的编排数据
                    ↓
用户模型及参数 → TerryDirector 主节点 → 下游解码 / 合并 / 保存
                    │
                    ├─ 内部计划整理与校验
                    └─ 内部逐段编码、采样与连续性处理
```

规划与执行是同一插件中的内部代码职责，通过普通数据结构传递，不增加服务或独立任务运行时。正常执行不要求浮窗处于打开状态。

运行实现优先沿用成熟的有限分段展开方式：一次 ComfyUI 提交，在内部保留各段依赖。ComfyUI 的节点扩展机制支持一个可见节点返回内部执行子图，并分别处理子节点缓存。依据：[官方节点扩展文档](https://docs.comfy.org/custom-nodes/backend/expansion)。不因只显示一个节点而另写外部逐段提交队列。

## 3. 画布上的节点外观

外观接近采样器：左侧为必要的模型与参数输入，右侧为生成结果输出，中间为紧凑控件及迷你时间轴。具体端口名称和尺寸在实现时确定，不在本轮假定全部接口已完成。

迷你时间轴：

- 显示已保存的片段排列、相对时长、重叠，以及片段数 / 总时长摘要。
- 只读；不提供拖动、裁剪、重排、资产投放或另一套时间线编辑手势。
- 点击迷你时间轴打开编辑浮窗；同时保留带文字的“编辑时间线”按钮，支持键盘操作。
- 有真实执行数据时才显示进度与结果状态；迷你时间轴不是视频播放器，不用素材缩略图伪装生成结果。
- 缩小画布时降低文字细节，不频繁重画完整编辑器。关闭浮窗后只更新必要的节点摘要。

完整编辑器与迷你时间轴读取同一份保存数据；可以复用时间几何计算，不能因此把完整编辑命中区域带到只读视图中。

## 4. 同页大浮窗

点击节点入口后，在当前 ComfyUI 页面显示大浮窗，遮罩下面的画布；不使用 `window.open`，不跳转地址，不启动第二个 Web 服务。

大浮窗以视口为基准，不随节点画布的缩放比例放大或缩小。继续使用现有 Studio Dark、圆角、留白和投影，移植已经确认的编辑区与单行时间线，不重新发明编辑器。当前 v0.6.13 的内部布局是移植起点，未确认的区域删除或重排不在本轮实施。

建议实现方式：使用 ComfyUI 前端扩展，在页面顶层挂载独立、带样式作用域的原生 DOM 容器。扩展生命周期参考[官方前端扩展说明](https://github.com/Comfy-Org/ComfyUI_frontend/blob/main/docs/extensions/core.md)。不能把当前 Demo 的 `body`、`#app` 全局样式直接注入 ComfyUI，不能覆盖宿主页面根节点。

交互要求：

- 编辑器中的输入、拖动、滚轮、复制、删除和撤销不得穿透到背景画布；保留中文输入法行为。
- 焦点留在浮窗内，退出后回到原节点入口。素材灯箱和菜单位于编辑浮窗之上，Esc 先关闭内部弹层，不直接丢弃整个编排。
- “保存并退出”提交编辑结果、更新节点摘要并隐藏界面；不是开始生成。
- 关闭按钮或 Esc 遇到未保存修改时，应提示保存、放弃或继续编辑；点击遮罩不能静默丢失内容。
- 再次打开恢复该节点已保存的编排及合理的编辑位置。一个编辑浮窗绑定一个明确的工作流节点实例；复制节点、切换工作流或删除节点不能误写另一节点。
- 隐藏时暂停编辑器动画、媒体播放及不必要的监听；后台已经提交的生成继续。运行事件仍可更新独立任务状态。

根目录静态 Demo 可以继续作为样式和交互预览入口，但它不是生产运行必须打开的第二个网页。两种承载方式复用编辑器代码，不维护两份业务 UI。

## 5. 保存、排队和运行的边界

建议把已保存的编排放在该节点的可序列化输入中，包含版本、片段、原始提示词、稳定素材引用、时间位置及必要配置。后端能从本次执行输入取得完整编排，不依赖浏览器内存或当前选中片段。

编辑浮窗使用草稿副本。保存后原子更新节点的正式编排值，并通知 ComfyUI 工作流已修改；这不等于已自动保存到用户磁盘，磁盘保存继续遵循 ComfyUI 工作流的实际机制。

队列执行使用提交时快照：

- 保存退出不自动排队，也不重复提交工作流。
- 有未保存草稿时，不允许把它悄悄当成已保存计划提交；正式入口应提示先处理草稿。
- 已排队 / 正在执行的任务不因打开编辑器、切换片段或再次保存而变化；后续修改影响下一次提交。
- 运行信息按本次任务及节点实例关联，不能仅以“当前选中节点”判断归属。
- 工作流内保存的是配置与媒体引用，不嵌入模型、图片二进制、视频张量或浏览器 `blob:` 地址。导入素材需有后端可读取的持久文件引用。

当前 UI Demo 的页内暂存和导出版本 9 只是迁移来源；正式序列化格式须有向后兼容处理，不在本轮冒充已完成持久化。

## 6. 采样器式输入与参数归属

以下是实现建议，不是已冻结的最终端口列表：主节点接受 `MODEL`、`CLIP`、必要的视频 / 音频 `VAE`、采样器及采样调度，随机种子等参数在节点上设置或接入。

外部已连接的参数是该次执行的实际来源。浮窗如显示同一参数，应读取或编辑同一份节点值；不要让节点和浮窗各存一套步数、分辨率或二采开关。外部连线驱动的值不能在浮窗伪装为本地可覆盖值。

二次潜空间放大保留已确认的能力需求，其开关与设置可以属于同一主节点；本轮不因为换成浮窗就删除该能力，也不加入工作流自动识别系统。采样调度从外部 `SIGMAS` 取得时，高清阶段步数按实际总步数校验，不能重复使用一个互相冲突的内部总步数。

“输出交给解码器”不代表主节点完全不需要 VAE。参考图 / 视频编码、部分二采算法以及首尾承接处理可能仍需要 VAE；最终成片解码和保存位于下游，与内部必要的参考编码或少量连续性解码区分。

目前 Demo 的分辨率为片段独立值，而参考生成链路常用共用尺寸；此处仍需在实现前统一执行约束。不能在同一条 latent 承接链中任意改变尺寸却宣称自动兼容。

## 7. 输出给解码器：必须保留的技术边界

**用户确认的是生成与最终解码分离；多片段输出的最终类型尚需验证。** 不在本轮承诺“一个普通 LATENT 端口连接任意 VAE 解码器，就能得到已经正确拼接的长视频”。

参考实现的文档明确写明：其“末段 sampled latent”只代表最后一段，并非整条视频的合并 latent；现有顺序是在 AV 解码之后进行重叠去重与合并。依据：[Songssx 有限分段说明（固定 a81f13b）](https://github.com/Songssx/ComfyUI-MiniMaxH3-TimelineDirector/blob/a81f13b8af4a162467cec4dc377f40b7354d7ffc/docs/FINITE_SEGMENT_EXPANSION_CN.md)。

我们的外部解码设计必须保留：各段实际采样结果、稳定片段身份及顺序、帧数与帧率、实际重叠裁切信息、音频时序与原音锁定信息。SelfLift 的低清 carry 留作内部续接上下文，不冒充最终输出。

候选实现顺序：

1. 单片段验证标准 H3 latent 经正确的视频 / 音频解码路径输出；必要时明确拆分 AV latent。
2. 多片段优先比较“分段 LATENT 列表 + 对应合并信息”与“结构化采样结果 + 薄的分段解码 / 合并节点”。选择能正确处理接缝且操作最少的方式，具体节点和端口另行收敛。
3. 标准解码器只能负责它理解的数据，不会自动解释我们的重叠、锁音或片段顺序；不能丢弃元数据来换取接口表面统一。

ComfyUI 的列表输出可以逐项调用下游节点，但列表不等于已经沿时间维拼接的一个 tensor，也不保证逐段即时流式执行。依据：[官方数据列表文档](https://docs.comfy.org/custom-nodes/backend/lists)。需要检查长视频 latent 驻留、卸载 / 存盘和峰值内存，不能只统计最终 RGB 是否放在主节点外。

成熟分段解码可优先复看 H3 Easy 的 `MiniMaxH3EasySegmentDecode` 与 Easy Media 的结果存储，依据仍按 [07 参考清单](07_REFERENCE_IMPLEMENTATIONS.md) 记录。引入配套解码辅助节点属于输出接口建议，不是重新要求用户使用两个导演台主节点；尚未作为本轮已批准实现落地。

## 8. 参考与实现红线

- Songssx 等仓库是实现参考与可依许可采用的来源，不是本项目运行时必须安装的导演台节点包；所有本项目内部 helper 与节点标识由 TerryDirector 自己提供。
- 保留现有计划校验、原始提示词与素材编号转换、前序 latent、音视频遮罩和二采上下文语义。换成单节点不能简化成互不相关的多条提示词。
- 不为表面端口兼容而移除连续性约束，不把上一段尾帧需求误记成参考实现已经满足的行为。
- 前端编辑、mini 时间轴、Python 执行模块分工保持清晰；一个可见节点不等于一个源文件。
- 不新增独立端口、第二进程、外部调度器、工作流管理平台、React 或后台技术监控。
- [QuantFunc](08_QUANTFUNC_RESEARCH.md) 继续暂缓；本次改架构不自动授权接入它。

## 9. 后续验收顺序

先验证同页浮窗的打开、编辑、保存退出、重新打开、工作流保存 / 重载、复制节点和多节点隔离，且隐藏后不持续占用编辑器渲染资源；迷你时间轴必须始终只读。

再用一个片段打通自己的主节点与下游解码；最后验证两段连续生成、重叠去重、音频锁定、SelfLift、任务取消及再次执行。显示成功、模型采样成功、合并成片成功分别确认，不互相替代。

本轮只归档这项产品决策与技术边界；没有运行浏览器或 GPU 验收，没有修改现有 Demo 实现。
