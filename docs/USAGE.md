# 使用指南

此文档描述当前 `main` 的实际接口和接线方式。基础模式、Advanced、循环器可分别使用，不要求把三种模式串在同一个工作流中。

## 1. 首次配置

1. 将 TerryDirector 安装在 ComfyUI 的 `custom_nodes/TerryDirector`，重启后搜索节点名。
2. 使用本机已有的 MiniMax H3 模型、CLIP、视频 VAE、音频 VAE 建立模型加载链。
3. 新建「TerryDirector 配置」，连入上述四类依赖，并选择宽高比、百万像素、采样器等参数。
4. 在主导演节点中点击迷你时间线，编辑提示词、图片资产与片段时间，然后保存并退出。
5. 第一次生成建议只启用一个短片段，再逐步测试多片段、尾帧参考和重叠衔接。

节点的配置随 ComfyUI 工作流保存；建议保留自己的 JSON 工作流副本。仓库不附带模型权重。

## 2. 基础 TerryDirector

连接顺序：

```text
模型 / CLIP / 视频 VAE / 音频 VAE
                 ↓
       TerryDirector 配置
                 ↓
          TerryDirector
                 ↓
       TerryDirector 输出
          ├─ 分段潜变量（LATENT 列表）
          ├─ 合并画面（IMAGE）──┐
          └─ 合并音频（AUDIO）──┴─→ CreateVideo → SaveVideo
```

基础模式适合还需要在 ComfyUI 下游继续处理完整画面／音频的工作流。分段在生成期间可以写盘、释放内存，但最终完整 IMAGE 仍需足够系统 RAM。

## 3. 内置 Self-Lift 二采

```text
TerryDirector 二采配置
          ↓
TerryDirector 配置
          ↓
TerryDirector / TerryDirector Advanced
```

只用本节点包内置 Self-Lift，不需要外部 selflift-Avatar 采样插件或额外打补丁脚本。主模型、CLIP、音视频 VAE 与目标分辨率继续由「TerryDirector 配置」提供，Seed 属于时间线节点。

连接有效二采配置后，普通采样器、调度器、总步数和 Denoise 会显示「二采接管」并变为不可编辑；断开二采后恢复原值。未连接二采配置时保持普通生成。

二采需要适配的放大模型权重；如果配置里没有所需权重，请检查 ComfyUI 的 latent upscale 模型目录。RTX 3090 参考的已验收参数见 [稳定基线](STABLE_BASELINES.md)。提高分辨率、启用高清空间分块或更换注意力后端，都会改变显存需求。

## 4. Advanced 高级导演

以 **TerryDirector Advanced** 代替基础主节点，同样接入「导演配置」。Advanced 自带视频保存设置和审片功能，支持选中片段局部重跑、中断后恢复，并采用无损分段缓存和最终单次编码以降低长视频生成期间的内存峰值。

Advanced 已使用分段文件化视频输出，不应该再将其导演输出当成完整的 IMAGE/AUDIO 使用。「TerryDirector 输出」的标准 IMAGE/AUDIO 拆包功能主要面向基础模式。

## 5. 时间线循环器（外部生成 / 解码链）

循环器面向需要自己搭建或替换普通 ComfyUI 生成节点组的用户；它并非独立的 H3 模型采样器。循环开始与唯一连通的循环结束之间会自动显示低透明度的 **圆角凸包「TerryDirector 循环域」**：它只是画布背景层的视觉范围，不创建 ComfyUI Group、不改变节点归属和执行逻辑；区域边界按从循环开始向下游可达、并在循环结束处闭合的节点自动计算。循环结束只负责接收**已经解码完成的 IMAGE/AUDIO**、写入无损分段缓存并形成下一段连续性上下文，不再接收视频 VAE / 音频 VAE，也不再负责 LATENT 解码。

```text
TerryDirector 循环开始
          │ 循环上下文
          ▼
TerryDirector 循环信息
          │ 提示词、采样帧数、Seed、image_0..8
          ├──────────────────────────────→ MiniMaxH3ReferenceToVideo / 自定义生成链
          │ 片段数据
          └─→ TerryDirector 循环条件
                     │
                     │        外部采样 / Self-Lift
                     │               │ LATENT
                     │               ▼
                     │        用户自己的解码节点
                     │          ├─ IMAGE ───────────────→ 循环结束 · 已解码画面
                     │          └─ AUDIO ───────────────→ 循环结束 · 已解码音频
                     │
                     └─ 当前片段元数据由循环器内部传给缓存，不需要接到循环结束

TerryDirector 循环结束
          │
          └─ 视频 VIDEO → 官方 SaveVideo
```

「循环上下文」和「片段数据」是两种不同的接口，不要混接。循环开始只输出循环上下文，循环信息解析成每段的提示词、帧数、Seed、素材及片段数据。循环条件决定如何使用上一段的尾帧和重叠上下文；实际模型、条件、潜变量、采样器、Sigmas 和解码器仍由用户在循环体中自由连接。

循环信息按官方 MiniMax H3 Reference to Video 的额度提供三类参考输出：**9 个图片、3 个视频、3 个独立音频**。端口分别为 `image_0..8`、`video_0..2`、`audio_0..2`。其中参考视频输出类型是官方节点要求的 **IMAGE 帧序列**，TerryDirector 会把 ComfyUI input 中的视频解码并重采样到 24 fps；独立音频输出为 AUDIO。官方还支持每个参考视频额外配一条同编号 soundtrack（最多 3 条），当前循环信息暂不自动输出这组配对音轨，避免改变已有 `<Audio N>` 独立音频编号语义。

循环开始节点支持可选的 **TerryDirector Llama 配置** 输入，与 Base / Advanced 共用同一套 AI 提示增强机制。连接后编辑器中的片段/全局 AI 增强按钮可用；开启「生成前自动AI增强提示」时，循环器会在展开逐段生成子图之前先执行 Queue 前增强，再把增强后的提示词交给循环信息节点。

循环结束对外现在只保留 **视频 VIDEO** 一个输出。它不再输出分段 LATENT，也不再提供「采样结果 / 视频VAE / 音频VAE / 片段数据」输入。当前片段的 ID、输出帧数、裁切/间隔、缓存签名与下一段上下文需求都由循环器内部传给隐藏缓存节点；用户只需连接最终的已解码画面、已解码音频，以及可选的「循环结束依赖」。需要查看或继续处理 LATENT 时，请直接在循环体的采样器输出处分支连接，不经过循环结束。

对于 **Self-Lift + 2X VAE** 工作流，推荐接线如下：

```text
SelfLift / H3 采样 LATENT
        ├─→ LTXVSeparateAVLatent → 清理节点 → MiniMax H3 VAE Decode (fast)
        │                                      │ IMAGE
        │                                      ├────────→ 循环结束 · 已解码画面
        │                                      └────────→ VHS Video Combine（可选，每段独立保存）
        │
        └─→ VAEDecodeAudio ─────────────────────────────→ 循环结束 · 已解码音频

```

2X VAE（例如 `MiniMax-H3-X2-Detail-v1.safetensors`）只属于用户自己的 Fast Decode 链。循环结束收到的就是最终解码画面，因此尾帧参考会从这组真实 IMAGE 中提取上一段尾帧。

如果希望每段分别由 `VHS Video Combine` 保存，需把 VHS 的 `Filenames` 输出接到循环结束的 **「循环结束依赖」** 输入。该输入不消费文件名内容，只用于告诉原生 Loop：这条每段保存分支必须完成后，当前循环才能结束。若只需要最终整条流式 VIDEO，则可以不接此依赖，直接把循环结束的 VIDEO 接官方 SaveVideo。

循环结束的「视频输出检查」会尽量沿已解码画面链追踪实际输出尺寸；对明确识别的 2X Fast Decode VAE 会显示推算后的尺寸并据此估算临时缓存空间。保存最终流式视频成功后，对应无损分段临时文件会自动清理；异常中断可能保留缓存供排查。

**当前范围**：默认适配器是 MiniMax H3；支持官方上限的 9 个图片、3 个视频和 3 个独立音频参考输入。LTX 2.5 仅保留模型适配占位，尚未接通自己的帧数、参考输入和连续性 Guide。循环体中的 Self-Lift、2X VAE、锐化/放大等节点由用户自由搭建。

## 6. 片段与素材

在节点内点击时间线打开编辑窗口。时间线支持时长调整、首尾吸附、片段重叠与挂起；「全局提示词」和「片段提示词」可以共同构成每段的生成提示。

将图片放在共享资产池，通过 `@` 菜单引用。镜头首尾关系包括「尾帧参考」「尾帧续接」「独立」，重叠关系由时间线计算。正在运行的节点编辑窗口会转为只读，但可以继续浏览片段与素材；未运行的其他节点仍可编辑。

ComfyUI → Settings → TerryDirector → 时间线 中可调整默认镜头衔接和尾帧参考提示词模板。


## 可选：AI 提示词增强

本功能不依赖额外安装 `ComfyUI_Qwen_H3_Prompt` 或 `ComfyUI-llama-cpp_vlm` 自定义节点。
仅在使用增强时才需要本机 Qwen3.8 GGUF 权重、对应的 `mmproj` 视觉投影器和兼容的 `llama-cpp-python` Python 包。
默认的 H3 文本/视频生成不要求安装这个 Python 依赖。

1. 将 GGUF 主模型及 `mmproj` 放在 `ComfyUI/models/LLM/`（可使用子文件夹），重启 ComfyUI。
2. 在运行 ComfyUI 的**同一个 Python 环境**中安装与本机系统/Python/CUDA 匹配的 `llama-cpp-python`。Qwen3.8 视觉功能需要支持 `Qwen35ChatHandler` 的构建，可参考 [JamePeng 发布包](https://github.com/JamePeng/llama-cpp-python/releases)；不要在已有 cu130 环境直接覆盖 torch。
3. 添加 **TerryDirector Llama 配置** 节点，选择 GGUF、mmproj、AI Seed（与视频 Seed 独立）。「系统提示词预设」下拉框默认选择 **H3 Skill**；「系统提示词」多行编辑区同时保留 STRING 插口，可直接编辑或从外部文本节点接入。
4. 系统提示词采用“**自定义文本优先、预设兜底**”规则：只要「系统提示词」去除首尾空白后仍有内容，就完全使用用户文本作为 system role，不再追加 H3 Skill 或 TerryDirector 内置 system/binding 规则；若为空、只有空格／换行／Tab，则视为没有内容，改用下拉框预设。选择「无」且文本也为空时，不发送 system role。连接「Llama 配置」到 **TerryDirector**、**TerryDirector Advanced** 或 **TerryDirector 循环开始** 后，手动增强、全局增强、批量增强和 Queue 前自动增强都遵循同一规则。若 Llama 配置节点处于 **Bypassed / Never** 状态，编辑器会将其视为不可用配置并禁用 AI 增强相关按钮；恢复启用后自动恢复。
5. 片段的「AI 提示增强」与「一键增强所有提示词」走 ComfyUI 本地 HTTP Job，**不提交 Queue**；片段原文和增强稿分别保存。
6. 在「全局提示词」弹窗也可切换「用户提示词 / AI 增强提示词」，点击「AI 提示增强」仅增强**全局人物设定、参考素材关系、摄影/视觉/声音约束**。全局内容不属于一个固定时长的片段，因此输出为适用于所有片段的英文约束说明，而非六节 Ref2VA 镜头输出。原文保留；保存时当前选中的全局版本参与时间线编译以及片段 AI 提示增强。
7. 编辑器顶部开关现名为 **「生成前自动AI增强提示」**。开启后，一次 Queue 自动增强**需要处理的片段**，再执行 H3；全局提示词需要用户在弹窗中**手动点击增强**，不会因运行 Queue 而暗中改写。Queue 自动增强遵循 ComfyUI 自身的 Stop/Interrupt：用户停止工作流时，流式 Llama 生成会在下一个 token 事件检查并立即中断，不再等待整段增强完成；编辑器中的独立手动增强仍只由它自己的取消操作控制。

**AI Seed 规则：** 对片段，首次没有结果时增强；已有 AI 结果且 Seed 相同则复用；修改原文、全局提示词、时长或模型只显示旧结果状态，不自动重做。更换 AI Seed 会重新增强片段；手动按增强按钮则强制重做对应范围。全局增强属于显式手动任务：再次点击即重新生成，修改全局原文只提示旧 AI 版本过期，不自动重跑。挂起片段和用户明确选择只使用原文的片段不参与 Queue 自动增强。

AI 仅处理当前片段自身的提示词、时长、当前引用的媒体及启用的全局约束；不提前模拟尾帧、重叠或相邻片段连续性。尾帧/重叠仍由既有时间线编译与采样过程处理。

**媒体边界：** 图片通过 VLM 读取；视频在可使用 OpenCV 时抽样最多四帧供 VLM 观察（未安装解码器时只传媒体名称，不假称已经分析视频）；音频文件目前只传名称，不做听觉内容分析。

**资源提示：** Qwen3.8 27B Q4 会占用大量显存。默认一次只允许一个 AI 推理任务，批量运行只加载一次模型，完成后清理资源。RTX 3090 环境下，基础三段含参考图的自动增强与 H3 视频链路已完成 GPU 实测，详见开发分支的 [AI 验收报告](AI_PROMPT_ENHANCEMENT_ACCEPTANCE_REPORT.md)。**后续新增的全局提示词手动增强仍需单独进行本机 GPU 回归**；GitHub Actions 只验证数据保存、编译行为和模拟 VLM 返回。

## 7. 常见问题

**节点缺失／导入失败**：先核对 ComfyUI 版本、模型和官方生成节点是否安装。已验证的系统版本在稳定基线文档中；其它环境需要自行验证兼容性。

**分段时长与采样帧数不同**：H3 采样长度必须按自己的合法帧数规则对齐，生成后再裁切至时间线需要的帧数，这是正常现象。

**视频输出占用很多磁盘**：流式 VIDEO 会将未压缩画面和音频先存为无损分段缓存，长视频需要足够临时磁盘；无需把完整时间线图像常驻内存，但仍需容纳当前片段解码与编码器的 RAM/VRAM。

**循环器无法直接接入 LTX 2.5**：目前仅预留 `ltx_2_5` 注册项，未实现帧数规则、Guide、音视频潜变量解码；不能把通用端口名称视为 LTX 已兼容。

**静态演示页无法生成**：根目录 `index.html` 用于预览创作 UI，正式生成请在 ComfyUI 节点图中执行。

生产模块和调用关系见 [架构说明](ARCHITECTURE.md)，稳定运行参数与来源见 [稳定基线](STABLE_BASELINES.md)。
